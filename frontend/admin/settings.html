Integration Endpoint: Receive Approved Ideas

External Ideation Tool Integration API — push approved ideas directly into QCMS using your API key.

POST /api/v1/integrations/ideas
Required Security Headers
Authorization: Bearer <YOUR_API_KEY>
Content-Type: application/json
⚡ Rate Limit: 100 requests / minute per API key
🔒 Key is SHA-256 hashed. Never expose raw key in logs.
API Response Specifications
201 Created — Idea Imported Successfully
{"success": true, "message": "Idea imported successfully.", "ideaCode": "IDA-2026-006"}
409 Conflict — Duplicate ideaCode (already imported)
{"message": "Idea already imported."}
401 Unauthorized — Invalid or disabled API Key
{"error": "Unauthorized", "message": "Invalid or disabled API Key."}
429 Too Many Requests — Rate limit exceeded
{"error": "Too Many Requests", "message": "Rate limit exceeded."}
400 Bad Request — Missing required fields
{"success": false, "message": "Missing required fields: 'ideaCode' and 'title'."}
Payload Field Reference
Field Type Required Description / Example
ideaCode string Required Unique ID from your Ideation Tool  "IDA-2026-006"
title string Required Short title of the idea  "Reduce Paint Defects"
presentSituation string Optional Current problem / pain point description
proposedSolution string Optional Suggested improvement or fix
department string Optional "Production", "Quality", "HR"
category string Optional "Quality", "Cost", "Delivery", "Safety"
submittedBy string Optional Full name of the submitter  "John Doe"
coSuggesters string[] Optional Array of co-author names  ["David", "Smith"]
tangibleBenefit number Optional Financial savings in ₹ (numeric)  100000
intangibleBenefit string Optional Non-financial benefit description
investmentRequired number Optional Capital or operational cost in ₹  250000
implementationTime string Optional Timeline estimate  "8 Weeks", "2 Months"
impactLevel enum Optional "Low" / "Medium" / "High"
status string Optional Default: "Approved"

8S Problem Solving User Manual

Detailed guide for completing all 8 stages of the QCMS 8S workflow.

Objective: Establish the cross-functional project charter, define the problem using the 5W2H framework, document baseline performance metrics, implement immediate containment actions, and plan the 8-stage milestone timeline.
Role Permissions: Editable by Admin and Team Leader; Team Members have view access; Facilitator & Reviewer review stage gate submissions.

Section 1.2 - Problem Background (5W2H Framework)
Field / Dimension Type Guiding Question Why Enter / Purpose System Integration Sample Data
What Happened? Textarea What is the exact defect, symptom, or failure mode? Clearly establishes the physical symptom observed on the shop floor. Synthesized into project charter and Stage 1 overview. 'Burr height exceeding 0.15mm specification on trim-edge.'
Where Did It Happen? Textarea Where is the failure observed physically? Pinpoints the machine station, die, cavity, or line location. Used in Stage 2 Stratification and 5G Gemba verification. 'Press Station PR-05, Upper Die Cavity 2, Chennai Plant.'
When Did It Happen? Textarea When did the issue start or occur? Identifies timing, shifts, batch start, or seasonal patterns. Correlated with Stage 2 Trend Analysis. 'Since 15-Jan-2026, predominantly during Shift B.'
Who Is Affected? Textarea Who detects the defect or suffers downstream impact? Identifies internal downstream operators or external customers impacted. Informs Stakeholder Communication in Stage 6. 'Next station assembly team and OEM customer QA.'
Why Is It A Problem? Textarea Why does this defect matter to quality or cost? Explains commercial, safety, or functional repercussions. Renders in executive summary dossier. 'Causes fitment jamming and risk of customer line stoppage.'
How Discovered? Textarea How was the problem initially detected? Clarifies if caught by automated sensor, manual inspection, or audit. Feeds Stage 4 Escape Point Analysis. 'Visual inspection during 100% end-of-line quality gate.'
How Big? (Impact/Cost) Textarea What is the magnitude, scrap rate, and financial loss? Quantifies initial severity before deep-dive measurement. Sets Stage 1 baseline for Stage 7 ROI realization. '4.2% reject rate, 320 parts scrapped, approx. ₹1.8L monthly loss.'
Problem Definition Textarea Concise formal problem statement. Standard problem statement summarizing Object + Defect + Extent. Propagates to Stage 3 Problem Restatement automatically. 'During Jan-Feb 2026, trim-edge burr defect on PR-05 increased to 4.2%, exceeding 0.5% target.'

Section 2.1 - Process Observation (Gemba Walk)

Section 2.2 - Standard Verification (3-Point Deviation Check & Early Closure Gate)
Standard Check Verification Options What to Check System Trigger / Logic Sample Entry
1. Standard Operating Procedure (SOP) Available (Y/N), Deviation (Y/N) Is an updated SOP available at workstation and followed by operators? If Deviation = 'Yes', requires deviation description. 'SOP-TR-04 available, but tool cleaning cycle skipped every 3rd shift.'
2. Technical Specifications Clear (Y/N), Deviation (Y/N) Are drawing tolerances, material hardness, and dimensional limits met? Records engineering spec adherence. 'Material sheet hardness is within 48-52 HRC specification.'
3. Control Plan Followed (Y/N), Deviation (Y/N) Are inspection frequency and sample sizes strictly executed as per Quality Plan? Identifies quality control gaps. 'Hourly burr height inspection not consistently recorded in log.'
Early Closure Gate Logic Special Feature: If all 3 checks show "No Deviations", the system automatically triggers an Early Closure Recommendation gate, enabling fast-track resolution if the issue was merely a non-standard execution glitch.

Section 2.4 - Instant QC Tools & Statistical Visualizations
QC Tool Visual Type Mathematical / Statistical Rule Decision Output
1. Trend Analysis Interactive Line / Area Chart Time-series plotting showing daily, weekly, or shift trend. Identifies sudden spikes, cyclical trends, or steady deterioration.
2. Pareto Prioritization Dual-axis Bar Chart with Cumulative % Curve 80/20 Rule: Ranks defect frequencies from highest to lowest with cumulative line. Isolates the "Vital Few" defect categories (typically ≤ 80%) for Stage 3 root cause analysis.
3. Stratification Analysis Multi-category Bar & Distribution Cards Slices data by Shift, Location, and Method to detect isolated clusters. Reveals if defect concentrates on specific shifts or specific machines.
4. Histogram Analysis Frequency Distribution Bars + Normal Curve Calculates Mean ($\mu$), Sample Standard Deviation ($\sigma$), and Range. Evaluates process spread and identifies skewness or multi-modal patterns.
Section 2.5 - 5G Problem Verification Framework
5G Principle Japanese Term Meaning & Guiding Action Sample Entry
1. Gemba Actual Place Go to the exact shopfloor workstation where the issue occurs. 'Inspected Station PR-05 during live Shift B production run.'
2. Gembutsu Actual Part/Object Examine the physical defective workpiece, tool, or die directly. 'Examined 20 rejected parts; burr is localized exclusively on upper right quadrant.'
3. Genjitsu Actual Facts & Data Collect verified numerical measurements rather than subjective opinions. 'Dial indicator measured 0.22mm burr height vs 0.10mm max allowance.'
4. Genri Operating Principles Check machine physical, mechanical, and chemical working principles. 'Punch cutting clearance requires uniform 7% sheet thickness.'
5. Gensoku Standards & Rules Verify whether standard parameters and maintenance rules were followed. 'Punch regrinding interval exceeded standard 10,000 stroke rule by 4,200 strokes.'

Tool / Matrix Type Purpose & Description System Output

Section 4.1 & 4.2 - Suspected Causes & 5-Why Analysis
Component Type Purpose & Method Sample Entry / 5-Why Chain
Suspected Causes List / Imported Prioritized cause list imported directly from Stage 3 screening. 'Punch blade cutting clearance uneven across die cavity.'
5-Why Drill Down Chain Iterative Step Table Iteratively asks "Why did this occur?" 5 times to traverse from physical symptom to underlying technical/management root cause. Why 1: Why did burr exceed 0.15mm? → Cutting edge clearance increased to 0.18mm.
Why 2: Why clearance increased? → Punch die shifted during stroke.
Why 3: Why die shifted? → Clamping bolts lost pre-load torque.
Why 4: Why torque lost? → No torque wrench used during die change.
Why 5: Why no torque wrench used? → Root Cause: Die change SOP lacked torque specification & verification checklist.
Section 4.3 & 4.4 - Cause & Effect Matrix and FMEA (RPN Calculation)
Analysis Tool Parameters / Inputs Mathematical Formula & Scoring Interpretation & Risk Thresholds
Cause & Effect Matrix Process Inputs (KPIVs) vs Customer Outputs (KPOVs) Correlation weights (0, 1, 3, 9) multiplied by customer importance ratings. Ranks KPIVs with the highest aggregate impact on customer satisfaction.
FMEA Table Severity ($S$), Occurrence ($O$), Detection ($D$) scored 1-10 $$\text{RPN} = S \times O \times D$$ High-Risk Action Triggers:
• $\text{RPN} > 100$: Mandatory countermeasure required in Stage 5.
• $S \ge 8$ (Safety/Critical failure): Mandatory immediate redesign regardless of RPN.
Section 4.5 to 4.8 - Hypothesis, Experimental Verification & Escape Point

Hypothesis Formulation Text Formal hypothesis testing statements ($H_0$: Null vs $H_1$: Alternative). '$H_1$: Die bolt torque < 120 Nm increases burr height above 0.15mm.'

2. Incomplete 4-quadrant first-piece inspection SOP.'

Objective: Brainstorm countermeasure solutions for each verified root cause, evaluate alternatives using decision criteria matrices, engineer Poka-Yoke mistake-proofing mechanisms, evaluate secondary risks, allocate budgets, and construct the 3W1H implementation plan.

Section 5.1 & 5.2 - Solution Brainstorming & Decision Evaluation Matrix
Evaluation Criteria Scale Scoring Description Decision Gate Outcome
1. Effectiveness 1 (Low) – 5 (High) How completely does the solution eliminate the root cause? Automated Scoring & Classification:
• Selected: High total weighted score (≥ 20/25); moves to Stage 6 execution.
• On Hold: Feasible but requires secondary budget review.
• Rejected: Low effectiveness or prohibitive cost.
2. Technical Feasibility 1 (Difficult) – 5 (Easy) Can it be engineered in-house or readily sourced from standard suppliers?
3. Implementation Cost 1 (High Cost) – 5 (Low Cost) Total tooling, hardware, software, and labor expenditure.
4. Execution Time 1 (> 2 Months) – 5 (< 1 Week) Speed of physical manufacturing installation and commissioning.
5. Safety & Ergonomics 1 (Hazardous) – 5 (Safe / Ergonomic) Zero negative impact on operator safety, pinch points, or repetitive strain.
