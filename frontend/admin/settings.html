Integration Endpoint: Receive Approved Ideas

External Ideation Tool Integration API — push approved ideas directly into QCMS using your API key.

POST /api/v1/integrations/ideas
Required Security Headers
Authorization: Bearer <YOUR_API_KEY>
Content-Type: application/json
⚡ Rate Limit: 100 requests / minute per API key
🔒 Key is SHA-256 hashed. Never expose raw key in logs.
API Response Specifications
201 Created — Idea Imported Successfully
{"success": true, "message": "Idea imported successfully.", "ideaCode": "IDA-2026-006"}
409 Conflict — Duplicate ideaCode (already imported)
{"message": "Idea already imported."}
401 Unauthorized — Invalid or disabled API Key
{"error": "Unauthorized", "message": "Invalid or disabled API Key."}
429 Too Many Requests — Rate limit exceeded
{"error": "Too Many Requests", "message": "Rate limit exceeded."}
400 Bad Request — Missing required fields
{"success": false, "message": "Missing required fields: 'ideaCode' and 'title'."}
Payload Field Reference
Field Type Required Description / Example
ideaCode string Required Unique ID from your Ideation Tool  "IDA-2026-006"
title string Required Short title of the idea  "Reduce Paint Defects"
presentSituation string Optional Current problem / pain point description
proposedSolution string Optional Suggested improvement or fix
department string Optional "Production", "Quality", "HR"
category string Optional "Quality", "Cost", "Delivery", "Safety"
submittedBy string Optional Full name of the submitter  "John Doe"
coSuggesters string[] Optional Array of co-author names  ["David", "Smith"]
tangibleBenefit number Optional Financial savings in ₹ (numeric)  100000
intangibleBenefit string Optional Non-financial benefit description
investmentRequired number Optional Capital or operational cost in ₹  250000
implementationTime string Optional Timeline estimate  "8 Weeks", "2 Months"
impactLevel enum Optional "Low" / "Medium" / "High"
status string Optional Default: "Approved"

8D Problem Solving User Manual

Detailed guide for completing all 8 stages of the QCMS 8D workflow.

Objective: Define the boundaries of the problem-solving effort, establish the team charter, assign responsibilities, and document baseline metrics.
Role Permissions: Editable only by Admin and Team Leader.
Section 1 - Project Team Details
Input Field Name Type Where Data Comes From Why Enter / Purpose System Impact Sample Data / Example
QC Circle Name Text Team brainstorming session or organizational directory. Establishes a group identity and organizes projects under a specific team folder. Saved in the database and shown on dashboard cards and exported report headers. 'Quality Avengers' or 'Welding Line-B Lean Circle'
Work Area Text (Readonly) Platform plant/line master data. Restricts the project scope to a specific manufacturing cell or line. Links this project to localized dashboard metrics and alerts local managers. 'Assembly Line B' or 'Machining Cell 3'
Sponsor Text (Readonly) User profiles database. Designates the executive sponsor who funds and authorizes the project. Shown in the project charter and included in closure notification emails. 'Jane Doe (VP Operations)'
Facilitator Text (Readonly) User profiles database. Designates the lean coach or facilitator who guides the team through QC tools. Grants review and guidance access to the project workspace. 'Amit Kumar (Senior Lean Coach)'
Team Leader Text (Readonly) User profiles database. Designates the primary owner who is responsible for S0-S8 execution and saving Stage 1 data. Grants edit permissions on Stage 1 and approval submission authority. 'Harshith (Quality Lead)'
Duration Text (Readonly) Calculated automatically. Provides an active duration tracking metric. Renders on dashboard cards as 'Days Active'. '24 Days'
Team Members Multi-select Table Organization user list. Builds the cross-functional team (typically 3-8 members from engineering, operations, and quality). Grants Stage 2-8 editing permissions to the selected team members. 'Rohan (Design Engineer) - FEA expert; Amit (Operator) - Weld station specialist.'
Section 2 - Problem Background (5W2H)
Input Field Name Type Where Data Comes From Why Enter / Purpose System Impact Sample Data / Example
What Happened? Text Area Defect report or customer alert log. Documents the physical defect observed on the part or process. Feeds the final problem statement summary. 'Radiator core weld joint leaks coolant during leak testing.'
Where Did It Happen? Text Area Process map or station operator log. Pinpoints the physical location of defect generation or detection. Guides the Gemba walkthrough in Stage 2. 'Station 4 of assembly line B (Weld Joint J-12).'
When Did It Happen? Text Area Shift log or QA timestamp log. Records the date, time, and shift to identify temporal correlation. Informs the time-based trend analysis in Stage 2. 'First observed on June 25, 2026, during night shift B.'
Who Is Complaining? Text Area Customer support CRM or inspection log. Tracks the internal/external stakeholder reporting the defect. Sets the communication and alert recipient. 'Toyota India (OEM Customer).'
Why Is The Customer Complaining? Text Area Customer complaint letter or warranty return log. Documents the impact on the customer's operations. Provides the customer voice parameter for priority scoring. 'Coolant leaks cause engine overheating during dyno tests.'
How Was It Discovered? Text Area WIP inspection check sheet. Identifies the inspection step or tool used to detect the issue. Used in Stage 3 to analyze the escape point. 'Bubble emission test during 1.5 bar air pressurization.'
How Big Is The Problem? Text Area Production yield logs and scrap accounts. Quantifies the physical and cost scale of the issue. Sets the baseline value for target calculations. 'Defect rate is 15% (150 out of 1000 radiators) over the last 3 runs.'
Problem Definition Text Area (Summary) Synthesized from 5W2H fields. Provides a clear, consolidated problem definition that aligns the team. Serves as the 'Effect' text in the Stage 3 Fishbone diagram. 'Toyota India reported that Weld Joint J-12 leaks coolant on line B radiators, discovered on June 25 during Night Shift B at a rate of 15%.'
Section 3 - Current Performance
Input Field Name Type Where Data Comes From Why Enter / Purpose System Impact Sample Data / Example
Current KPI Text Monthly line scorecard. Establishes the baseline target metric. Saved as the benchmark to show 'Before' vs 'After' improvement in Stage 7. 'Defect Rate (ppm)' or 'Scrap Cost ($)'
Current Defect Rate Text Quality scrap records. Establishes baseline defect frequency. Used to calculate percentage reduction in Stage 7. '15.0%' or '150,000 ppm'
Current Complaint Count Number CRM customer return database. Establishes baseline of formal customer complaints. Used for external validation in Stage 7. 3
Current Cost Impact Text Accounting scrap ledger. Financial quantification of the current losses. Provides comparison metrics for ROI calculation in Stage 7. '$12,500 per month'
Current Downtime Text Machine PLC logs / maintenance database. Operational downtime quantification. Used to calculate total equipment effectiveness (OEE) improvement. '14.5 hours per week'
Section 4 - Justification Matrix
Input Field Name Type Where Data Comes From Why Enter / Purpose System Impact Sample Data / Example
Financial / Customer / Quality / Safety / Delivery / Regulatory Impact Text Areas Operational managers / Plant accountant. Explains why the project is important in all business dimensions. Provides the business case for executive management approval. 'Customer: Risk of line stoppage at Toyota. Safety: Coolant spills on shop floor present slip hazards.'
Why Should The Organization Work On This? Text Area Team consensus. The final justification statement for allocating engineers and operators. Displayed on project initiation charter. 'To avoid a massive $50k penalty from Toyota and ensure operator safety on Weld Line B.'
Section 5 - Emergency Response
Input Field Name Type Where Data Comes From Why Enter / Purpose System Impact Sample Data / Example
Containment Action Text Area Production manager immediate orders. Immediate, short-term actions to isolate the defect (implemented in 2 hours). Flags the project as 'Contained' on dashboard cards. 'Quarantine all finished stock in Warehouse C; perform 100% manual inspection.'
Responsible Person / Start / End Date / Status Table Grid Team leader assignments. Assigns direct ownership and target timelines for containment. Tracks emergency task execution. 'Rohan; Start: June 25; End: June 26; Status: Completed.'
Section 6 - Theme, Target & Schedule
Input Field Name Type Where Data Comes From Why Enter / Purpose System Impact Sample Data / Example
Improvement Theme Text Team brainstorming. Primary project name that summarizes the goal. Shown as the main subtitle of the project. 'Reduction of Radiator Weld Joint J-12 Leaks'
Current Level / Target Level Text KPI baseline vs target. Quantifies the project target goal. Renders progress bars and targets in dashboard comparisons. 'Current: 15.0%, Target: <0.5%'
Expected Benefit / Expected Savings Text Cost calculations. Estimates expected savings. Prioritizes this project in the active queue. 'Benefit: Zero Toyota penalties; Savings: $150,000 annually.'
Stage-wise Timeline / Milestones Dynamic Table Project manager plan. Planned date for each of the 8 stages. Draws a project GANTT/schedule line. 'Stage 2 Planned: June 28; Stage 4 Planned: July 5; Stage 8 Planned: July 25.'
